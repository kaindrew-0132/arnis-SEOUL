# Safe in-plane storefront integration
The previous bounded Overpass run 45823888310 timed out without data. A separate one-shot direct OSM API request for the three existing candidate way IDs, followed by their nodes, avoids the district-wide query. It cannot determine road orientation or occupancy; no automatic approval. Both requests are bounded, no retries. Attribution remains in the output artifact. Mapcarta candidate hints are not source geometry.

The ordinary Arnis wall-ring generator now has an opt-in, fail-closed in-plane storefront path. It needs a reviewed approval keyed to the exact OSM way, two adjacent node identities, exact 1:1 projected cardinal segment length, horizontal offset and width, approved height and a known material pattern. The registry is intentionally empty until actual geometry, reference date, occupancy, facade orientation and extent have been reviewed. No automatic world changes are made today. The path only changes existing eligible wall columns, preserving ordinary doors, corners, party walls, passages, photos and upper floors; no off-footprint writes or generic glass backing for overridden cells. It is limited to unrotated Java 1:1 empty shells and single reviewed facade per way. Separate 3D schematic fronts (sails, doubled skins, planting, etc.) remain unplaced; the in-plane material approximation is not a full 3D installation. Other wall decorations may still need integration validation. Tests cover reversal, bounds, changed footprint and missing/duplicate approvals.
